# 일정 캘린더

React + Vite와 일반 CSS로 만든 주간 일정 관리 앱입니다. 서버나 유료 서비스 없이 브라우저 localStorage에 일정을 저장합니다.

## 실행

Node.js 22 이상과 npm을 사용합니다.

```bash
npm ci
npm run dev
```

클라우드에서 기본 npm 캐시에 쓰기 권한이 없다면 `npm ci --cache /workspace/.npm-cache`를 사용합니다.

```bash
npm run build
npm run preview
```

프로덕션 결과물은 `dist/`에 생성됩니다.

## 사용 방법

- 월요일~일요일 주간 달력, 이전·다음 주 및 오늘 이동
- 날짜 칸 아래 `＋`를 누르면 새 일정이 생성되고 제목 입력란이 바로 열립니다.
- 일정 제목을 클릭하면 바로 수정할 수 있습니다. Enter 또는 바깥 클릭으로 저장하고 Escape로 취소합니다. 빈 제목은 저장하지 않습니다.
- 달력에서는 제목을 한 줄로 표시하고 넘치면 말줄임표로 표시합니다.
- 일정에 마우스를 올리거나 키보드 포커스를 이동하면 `×` 삭제 버튼이 나타납니다. 터치 기기에서는 항상 표시합니다.
- 삭제 시 확인창 없이 즉시 실행하며, 하단의 복구 버튼으로 10초 안에 메모·완료 상태까지 복원할 수 있습니다. 각 삭제 건에 독립적인 복구 시간이 적용됩니다. 새로고침하면 복구 대기는 종료됩니다.
- 오른쪽 날짜 제목 아래에는 그날의 공용 메모가 표시됩니다. 그 아래에는 선택한 날짜의 모든 일정이 펼쳐집니다. 일정이 많으면 패널 안에서 스크롤합니다. 달력 검색·필터와 관계없이 선택한 날짜 전체를 보여줍니다.
- 주간 달력의 일정 앞 체크박스로 완료 상태를 바로 변경할 수 있습니다. 오른쪽에서도 제목 수정, 완료 체크, 전날·다음날 이동, 삭제가 가능합니다. 날짜를 옮겨도 메모와 완료 상태를 유지합니다. 전날·다음날 버튼은 각 메모 아래 중앙에 표시됩니다.
- 빈 일정별 메모는 기본으로 숨기고, 다음날 버튼 옆의 작은 ＋를 누르면 작성할 수 있습니다. 이미 작성된 메모는 유지됩니다.
- 메모는 클릭하여 편집하며 각 줄 앞에 `·`가 붙습니다. 빈 항목에서 Backspace로 머리말을 지울 수 있으며 한 번 더 누르면 앞줄로 합쳐집니다. 내용에 맞춰 높이가 자동 조절되고, 바깥을 클릭하면 읽기 상태로 전환되며 테두리가 사라집니다.
- 상단에는 전체·오늘 진행률, 완료·남은 작업 수, 체크박스가 있는 오늘 일정 목록이 표시됩니다.
- 주간 달력과 오른쪽 목록은 데스크톱 800px, 모바일 700px 높이로 고정됩니다. 일정이나 메모가 많아져도 전체 높이는 유지되며 내부에서 스크롤합니다.
- 모바일에서는 주간 달력을 가로로 넘겨 볼 수 있습니다.

기본 서체는 Pretendard, 본문 크기는 10pt입니다. `public/fonts`에 폰트와 SIL OFL 라이선스를 포함하므로 외부 글꼴 서버 연결이 필요하지 않습니다.

## 데이터 저장

기본 일정은 2026년 10월 22일~11월 4일의 14개 작업입니다. 일정·완료 상태·일정별 메모는 `flatpoint-planner-v1` 키에 저장됩니다. 오늘 날짜는 사용자 기기의 현지 날짜를 따릅니다. 오늘 일정이 없으면 오늘 진행률은 0%입니다.

브라우저와 사이트 주소별로 저장되며 기기 간 동기화는 지원하지 않습니다. 브라우저 데이터를 삭제하면 기록도 사라집니다. 저장에 실패하면 화면에 안내합니다. 하루 메모는 날짜별로 `flatpoint-planner-memos-v2`에 별도 저장하며 기존 날짜별 메모도 다시 표시합니다. 일정별 메모와 하루 메모는 서로 섞이지 않습니다. 이전 공용 메모 키는 삭제하지 않습니다.

## GitHub Pages 배포

공개 주소: https://10ne2.github.io/plan/

```bash
npm run build -- --base=/plan/
```

`dist` 내용을 `gh-pages` 브랜치 루트에 배포합니다. 빈 `.nojekyll`을 포함하고, 하위 경로 새로고침 지원이 필요하면 `index.html`을 `404.html`로 복사합니다. GitHub Settings → Pages에서 `gh-pages` 브랜치의 `/ (root)`를 선택합니다.

배포 후 Actions에서 최신 gh-pages 커밋의 `pages build and deployment` 실행이 초록색 성공 표시로 바뀌면 공개 페이지를 새로고침합니다. 같은 주소의 브라우저 저장 데이터는 유지됩니다.

## Netlify 배포

1. Netlify의 **Add new project → Import an existing project**에서 저장소를 연결합니다.
2. 빌드 명령은 `npm run build`, 게시 디렉터리는 `dist`입니다. `netlify.toml`에 설정되어 있습니다.
3. 환경 변수나 API 키 없이 배포할 수 있습니다.

수동 배포는 `npm ci && npm run build` 후 `dist` 폴더를 Netlify에 업로드합니다. `public/_redirects`가 `dist/_redirects`로 복사되어 하위 경로 새로고침도 지원합니다.

## 구조

```text
src/App.jsx                    일정 상태, 저장, 삭제 복구, 주간 이동
src/components/Calendar.jsx    주간 달력, 날짜별 추가·삭제
src/components/InlineTitle.jsx 클릭하여 제목 편집
src/components/DayAgenda.jsx   선택 날짜의 전체 일정·메모
src/components/Memo.jsx        일정별 메모 편집과 자동 높이
src/data.js                    기본 일정과 날짜 처리
src/styles.css                 반응형 스타일
```
